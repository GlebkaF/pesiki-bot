## Три самые красивые идеи, которые вероятнее всего не окупятся

1. **REASON-4 «командный оптимизатор» без планов людей.** Составить непротиворечивую таблицу предметов легко; договориться сживыми людьми и учесть индивидуальныйтемп трудно. Данныеobserver недостаточны. Оставить простое «выоба началиX —согласуйте» только приподтверждённых intentions, а не глобальное распределение utility.
2. **DATA-3 «персональные Turbo cohorts» как сильный сигнал выбора.**403реплея выглядятмного, но нарезка player×hero×role×patch×draft быстро оставляетединицы;возможно learn team's bad habits. Оставить retrieval конкретных примеров ипрозрачные descriptive counts. Не обещать норму/оптимальнуюсборку.
3. **REASON-6 «вторая LLMсделает безопасно».** Общиеисточники,общиеblindspots,дополнительныезадержки идорогие ложныеотказы. Typed template plus validated reasoning relations —лучшийbaseline; onlineverifier разрешатьтолько после ablation, показывающего дополнительнуюпользу.

Близкий риск — REASON-1 всеобъемлющий mechanics graph. Узкоеядрообязательно, полнаяонтологияDota сомнительнаэкономически. Не подменять uservalue длительнойmanualcuration: сначала10–20реальных вопросовстака иодин decisionfamily,измеритьтрудозатраты поддержания иcoverage.

## Скрытые общие риски

- Если всеfanoutагенты читаютодинкод иодни3бага, ихсогласие коррелировано. Финальныйredteamдолжен включитьновые независимосозданные cases, не только перестановкуGreaves/BKB/Weaver.
- Граница«совет верен» vs«совет полезен» фундаментальна. Правильные эффекты+правильныйполучатель не доказывают целесообразность тратить золото. Эксперт вправе сказать«допустимо, но бесполезно».
- Delayed advice обязанпроверятьсяпосостояниюt+actualLag, при этом выбратьрешение можнотолькопоt. Толькоagebadge неустраняет этуасимметрию. Будущиеполя допускаютсявотдельном evaluator, неplanner.
- Исчезновение команды«сейчасатакуй» неустраняетfog leak: скрытаяпокупка можетизменить стратегию. Playerprojection доcandidate retrieval —не UIподпись.
- Humanreview можетнеокупитьсядля10игроков: сначала30случаев×2оценщика, засечьреальноевремя, стоимостьrulemaintenance,полезныевыводы. Еслиusersнехотятчитать, лучшеодинpostgameэпизод ипредыгроваяпамятка, чеммасштабированиеin-gameкарточек.
- Неиспользоватьsamplethresholds30/60/200какcertificate. Нужны покрытие, независимость, классыошибок,confidenceintervals. Дляредкихкритическихошибок маленькийpilot не даётсильнойстатистическойгарантии.


## Дополнительный критический red-team вывод: delay contract

REASON-2 и любая EVAL-3 формула delay120+age не доказаны: ROOT установил, что120 — поле SourceTV lobby, но не проверена семантика временного сдвига GetRealtimeStats. До clock alignment нельзя объявлять actual lag120 и строить latency SLA из него. Kill test: добровольный матч, одновременно записанные player game clock/видимый inventory и API state сreceivedAt/eventTime; несколько переходов предметов иgame clock; отделить transport/cache/generation, не считать ageдважды.
