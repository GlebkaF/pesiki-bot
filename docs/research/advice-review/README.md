# Аудит гипотез советчика

6 октября 2026. Три ветки сформулировали по семь гипотез. DATA и REASON получили по две перекрёстные проверки, EVAL — одну. Root дополнительно проверил production-данные, текущий валидатор и предположение о задержке источника, затем свёл результаты. Это исследовательская проверка идей агентами; человеческая оценка игровых решений ещё не проводилась.

Основной результат — [шесть выбранных решений и план проверки](../../advice-system-design.md). Ниже сохранён след отсева, а не список задач, которые надо все реализовать.

| ID | Исходная гипотеза | Итог после атак | Главный контрпример / необходимое изменение |
| --- | --- | --- | --- |
| DATA-1 | Контракт достаточности данных | Оставить, уточнить | Полнота и свежесть не доказывают доступность факта игроку или полезность совета |
| DATA-2 | Объединение кандидатов и квоты | Переработать | Большой recall можно получить всеми предметами; проверять качество top-choice, фиксированные квоты не обоснованы |
| DATA-3 | Персональные Turbo cohorts | Отложить ранжирование | После деления по герою/роли/патчу остаются малые и смещённые группы; описательные примеры допустимы |
| DATA-4 | Напоминания о повторяющихся ошибках | Отклонить для live v1 | Несколько смертей и отсутствие item_uses не доказывают упущенную возможность; оставить проверяемые эпизоды после игры |
| DATA-5 | Журнал решений | Оставить | Лог только удачных генераций скрывает пропущенные возможности; нужны отказы и независимый от модели отбор моментов |
| DATA-6 | Рандомизация для доказательства пользы | Отложить причинные выводы | Малый стак, перенос обучения и взаимодействие игроков; сначала диагностический пилот, без заявлений win-rate uplift |
| DATA-7 | STRATZ capability spike | Только при конкретном пробеле | Несколько удачных запросов не подтверждают покрытие production; не зависимость запуска |
| REASON-1 | Типизированный граф механик | Сузить до сценариев | Верный эффект не доказывает применимость и лучшую покупку; полная онтология слишком дорога в поддержке |
| REASON-2 | Типизированный контекст | Оставить | Скрытые предметы могут влиять уже на кандидатов; проекция до поиска и ранжирования |
| REASON-3 | Планировщик покупки | Переработать | Защитный предмет может проигрывать темпу; компоненты создают sunk-cost ловушку; нужны разные действия и baseline |
| REASON-4 | Командное распределение | Отложить автоматизацию | Независимые обновления переназначают предмет двум людям; нужны подтверждённые намерения и стабильная версия |
| REASON-5 | Частичный отказ | Оставить с метриками пользы | Молчание на сложном и банальности на простом дают ложное качество; вопросы не считаются готовыми советами |
| REASON-6 | Второй LLM-проверяющий | Отклонить как обязательный runtime | Общий ошибочный источник проходит обе модели; задержка и ложные отказы могут ухудшить результат; оставить offline red team |
| REASON-7 | Независимый benchmark | Оставить | Будущее из реплея и соседние снимки одного матча создают ложную точность; разделять матчи и оценивать тогда доступный вход |
| EVAL-1 | Контекст, доступный игроку | Оставить консервативный контракт | Terse feed не доказывает фактическую видимость; проверяем происхождение и изоляцию, не выдаём сертификат visibility |
| EVAL-2 | Следующий выбор вместо полного билда | Оставить | Приемлемый предмет может быть банальностью; отдельно оценить выбор, объяснение и полезную новизну |
| EVAL-3 | Устойчивость к задержке | Оставить после уточнения времени | SourceTV delay не измеренный лаг endpoint; проверить реальные переходы, stale и superseded ответы |
| EVAL-4 | Ошибка вместе с покрытием | Переработать пороги | Малые зависимые выборки не дают гарантии ≤1%; заранее определить scope, считать вопросы и отказы отдельно |
| EVAL-5 | Пользователь выбирает проблему | Оставить необязательную цель | Самодиагноз может быть ошибочным; не подтверждать его автоматически, не заставлять заполнять анкету в бою |
| EVAL-6 | Личная память | Только предпочтения и эпизоды сначала | Traceability не доказывает причинный вывод о привычке; отсутствие событий не равно отсутствию действия |
| EVAL-7 | Добровольная координация | Минимальная версия, позднее | Отмеченное пользователем согласование не доказывает предотвращённый конфликт; сравнивать с обычным голосовым общением |

Численные пороги и объёмы выборок внутри исследовательских заметок — предложения их авторов, не утверждённые гарантии. При расхождении финальный дизайн имеет приоритет. Предложенные эксперименты не считаются выполненными только потому, что они описаны. Архив содержит отвергнутые идеи специально для прослеживаемости решений.

## Слепое сравнение решений одного живого матча

[Анонимизированный результат](blind-audit-9032160861.json): 7 окон Turbo, 28 решений для игроков. Модель сформировала 25 целей; сервис вернул 12 карточек. Это разные знаменатели: четыре ранние генерации были целиком сняты старой проверкой изменившегося состояния. Исправление этой проверки уже выкатили отдельно; эти исторические данные не измеряют доступность текущей версии. Возврат сервисом также не доказывает, что человек увидел совет.

17 из 25 сгенерированных целей входят в условный набор автоматического слепого reviewer. Это **не точность**: набор не исчерпывающий, его условия ещё нужно проверять; совпадение предмета не доказывает полезность. Reviewer предпочёл сначала уточнить маршрут/намерение либо решить небольшую покупку в 18 из 28 случаев. Это не основание вернуть отвергнутую пользователем подсказку компонентов.

Конкретный дефект покрытия: в текущей библиотеке нет Manta, Blade Mail, Witch Blade, Vessel, Atos, Assault, Halberd, Basher, Scepter. Они встречаются среди условных альтернатив reviewer, но модель не может их выбрать. Приоритет следующей проверки — первые пять как воспроизводимые случаи для Riki, Legion и Invoker. Расширять надо с проверенными механиками и проверкой выбора на снимках; совпадение с reviewer нельзя делать целевой метрикой оптимизации.

Повторяемое соединение: `python3 tools/audit-advice-blind-review.py JOURNAL REVIEW OUTPUT`. Приватный журнал и исходная разметка не публикуются; результат не содержит аккаунтов и никнеймов. Контекст одной игры, исторические версии движка, автоматическая оценка — независимой экспертной проверки пользы ещё нет.
