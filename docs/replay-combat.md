# Расширенная аналитика реплеев

Текущий парсер — `pesiki-replay-v6`, схема `combat-log-v2`. Новые поля находятся в `ParsedMatch.analytics_version` и `ParsedPlayer.combat_details`. Старый JSON без этих полей остаётся читаемым: отсутствие данных не превращается в ноль. Код и локальные проверки готовы; публичную приёмку проводят после развёртывания.

## Повторный разбор сохранённых архивов

`src/backfill-combat-details.ts` работает офлайн: не обращается к API, не скачивает реплеи и не отправляет сообщения. Архивы `*.dem.archive` сохраняются; распакованные временные файлы удаляются после каждого матча. Перед массовым запуском сделайте резервную копию SQLite. Запускайте один процесс для данного каталога данных: файл отчёта общий.

Сборка из корня репозитория:

```sh
(cd tools/replay-parser && go build -o replay-parser .)
npm run build
```

Точечный запуск по ID матчей, без пробелов между ID:

```sh
DATA_DIR=/path/to/persistent/data \
REPLAY_PARSER_BIN=tools/replay-parser/replay-parser \
TARGET_PARSER_VERSION=pesiki-replay-v6 \
TARGET_ANALYTICS_VERSION=combat-log-v2 \
MATCH_IDS=8995355928,8995877480 \
node dist/backfill-combat-details.js
```

Без `MATCH_IDS` обходятся все сохранённые архивы. `REPLAY_ARCHIVE_DIR` переопределяет стандартный `$DATA_DIR/replay-archives`. Матчи с совпадающими версиями и заполненными данными пропускаются; повторный запуск продолжает незавершённую работу. Версия целевого парсера должна соответствовать указанному бинарнику.

Отчёт — `$DATA_DIR/combat-backfill-report.json`: `updated`, `skipped`, `failures`, время начала/окончания. Он атомарно обновляется, но каждый запуск создаёт новый отчёт. Ошибки отдельных матчей не останавливают остальные; код завершения при ошибках — 1. При свободном месте менее 3 GiB обход прекращается. На один запуск парсера установлен лимит 180 секунд.

`mergeReplayAnalytics` сверяет идентичность и состав, затем обновляет аналитику транзакционно. Старые официальные KDA и другие обогащённые поля сохраняются; понижение версии отклоняется. Проверяются прежние действия, APM и точная длительность. Определение APM остаётся `spectator-orders-v1`: одна spectator-команда между состояниями игры 5 и 6, независимо от числа выбранных юнитов. Исторические значения APM не пересчитываются по новой методике.

## Значение полей и ограничения

- **Лечение:** `self`, `other_heroes`, `units`, источники и получатели. `other_heroes` само по себе не означает союзников: сторона проверяется по составу. V6 отделяет получателей-иллюзий ключом `illusion:<hero>` и ставит `coverage.healing_target_identity=true`. В старом V2 при `units>0` без этого признака союзное лечение неизвестно; такие матчи можно точечно перепарсить. Источник `unknown` нельзя автоматически называть регенерацией.
- **Урон:** агрегаты по способности, цели и типу для настоящих героев, без иллюзий-атакующих и иллюзий-целей. `unknown_or_attack` не доказывает обычную атаку. Карта входящего урона перед смертью включает также наблюдаемый урон от существ и иллюзий, без выдуманной атрибуции владельцу.
- **Смерть:** координаты берутся из явного события либо состояния сущности героя (`coordinates_source`). `incoming` содержит суммы за последние 8 секунд по атакующему и способности. После смерти окно сбрасывается. Лимит — 4096 событий урона на героя; `complete=false` отмечает усечение окна, а не полноту всех игровых механик.
- **Варды:** `purchase` — покупка, `place` — создание настоящей сущности варда с проверенным владельцем, `destroy` — событие уничтожения. Старые `obs_wards_placed`/`sentry_wards_placed` фактически считали покупки и не используются как доказательство размещений. Новые размещения учитываются после начала игры; карта событий не восстанавливает fog of war.
- **Касты и контроль:** журнал кастов ограничен 5000 событиями на героя, журнал модификаторов — 2000, золота — 10000. Пропуски отмечаются `dropped_events`. Длительности контроля могут перекрываться и не складываются в уникальное время оглушения.
- **Экономика:** индекс 0 минутных массивов соответствует минуте 1. XP — накопленные наблюдаемые события, LH/denies — счётчики парсера. `coverage.xp=false` означает отсутствие подтверждённого XP. Золотые события — изменения с причиной, не баланс; имущество не равно заработанному золоту.

## Подписи и происхождение

`src/ability-labels.ts` использует статический каталог: [Valve KV, зеркало d2vpkr, commit 5ad3d91](https://github.com/dotabuff/d2vpkr/tree/5ad3d91b88d39014c30f772ca71061f5686ca5de/dota/scripts/npc/heroes) и [подписи OpenDota, commit e7705ee](https://github.com/odota/dotaconstants/tree/e7705ee975ebec2a88a59a7b455d4cae5dc69ca1/build). Классификация Ultimate опирается на явный `AbilityType`; неизвестное остаётся `null`. Каталог текущий, а не доказательство патча старого матча. Valve относит к Ultimate также некоторые вспомогательные кнопки: число таких событий не равно числу успешных применений ульты.

Типы урона `1/2/4` и причины золота расшифрованы по [схеме игры, commit a7122b4](https://github.com/SteamDatabase/GameTracking-Dota2/tree/a7122b414f20d0766e4273dbf7b4eab5611c842a/DumpSource2/schemas/client). Неизвестные коды показываются явно.

Проверки: Go `go test ./...`, `src/test-match-insights.ts`, `src/test-ability-labels.ts`, `src/test-player-profile.ts`, `src/test-retro-integrity.ts`; реальные реплеи дополнительно проверялись на совпадение сумм и прежних APM.
